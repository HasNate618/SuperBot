# Brain — Design (instruction following)

- Date: 2026-10-31
- Status: draft for review; no implementation until this document is accepted
- Scope: how the simulated G1 decides what to do when the task arrives as **speech plus one still**, from which facts, at what rate, and what it is allowed to emit. First writer: Job Simulator (museum hub, then Store Clerk). Does **not** implement the targeting adapter, projection, packet, game launch, or model serving.
- Replaces: `docs/superpowers/specs/2026-10-30-brain.md` (Superhot paint / arbiter / d1-as-kind). That document is historical. Do not implement it.
- Parent: `docs/2026-10-23-vr-bot-design.md` §5 (loops), §7 (body), §8 (adapters), §9 (brain). Adapter: `docs/superpowers/specs/2026-10-30-targeting-adapter.md`. Intent: `superbot/intent.py` (`superbot.intent/1`). Language/execution split: `research/g1-language-to-action.md`. Dual-system precedent: `research/system1-game-agents.md`.
- Target machine: existing NixOS/Hyprland host. Do not take over the host desktop. This spec does not launch a game.

Claim tags: `[MEASURED]` local file or named run; `[OPERATOR]` told by the person who owns the game; `[CITED]` a source with a URL; `[VENDOR]` a vendor number, unverified here; `[ASSUMPTION]` inference, untested.

## 1. Problem

The join works and the intent socket exists: a writer names `skill + side + optional pixel`, the adapter compiles that into `BodyCommand`s, the body never hears about a game `[MEASURED: superbot/intent.py, docs/superpowers/specs/2026-10-30-targeting-adapter.md]`.

Parent §9 asked a **classifier** over a still and a short digest: skill + side, no 3D point, only in hold. The Superhot brain (2026-10-30) then specialised that into paint gates, a threat digest, and a code arbiter. That is the wrong specialisation for the claim we are making now.

The claim is **instruction following**. A voice in the world tells the robot what to do. The brain has almost no prior on the game. It hears, looks, emits one legal skill, sees the outcome, and tries again.

Job Simulator is the first writer because it *is* that loop: JobBot speaks, objects sit in reach, success is the next sentence or a visible change `[CITED: https://jobsimulator.fandom.com/wiki/JobBot]`. Superhot remains a possible later adapter on the same socket. It is not this spec.

## 2. Claim

A G1 that, given a **minimal seed** and live speech plus one image, emits a valid `superbot.intent/1` and eventually completes spoken chores it was not scripted for.

Sequences are not compiled in Python. The model authors them across turns from `done / saturated / timeout`. If card → cartridge → slot → lever is a `HubFSM` in code, the brain is fake.

## 3. What makes this possible

In order. The model is last.

**1. A closed motor vocabulary.** Skills are `superbot.intent/1` (rejected if unknown) `[MEASURED: superbot/intent.py]`. Language is open. Motors are not. That is SayCan, not RT-2 `[CITED: research/system1-game-agents.md]`. The planner names a skill and a noun. It never names joints, an OpenXR pose, or a 3D point.

**2. Intent ≠ execution.** "Take a ticket" is two problems: grounding a noun in the image, and moving a hand. The adapter already owns the second. This spec owns the first, plus the choice of skill `[CITED: research/g1-language-to-action.md §1]`.

**3. The world waits.** Job Simulator does not shoot while we think `[ASSUMPTION: genre; not measured here]`. Thinking still happens only in freeze-hold so the wrists do not drift during a slow call. Freeze-hold is a body fact (last achieved poses), not a Superhot clock claim. Superhot G0 is not a gate for this spec.

**This is the weakest joint in the document, and it is stated as such on purpose.** The Superhot design was licensed by a *measured* clock (`minTimescale = 0.005 [MEASURED: research/wbc-game-proposal.md]`); this one is licensed by genre intuition. It is cheap to convert into a measurement and it should be, before B1: hold freeze for 20 s in a live Job Simulator scene and diff the stills. If nothing changes state — no objective timer, no JobBot re-prompt, no despawn — the assumption becomes a measurement. If something does change, the one-skill-per-turn cadence needs a shorter deadline. Do not leave this as an assumption once a session exists to test it in.

**4. A generative omni, not a decision head.** d1 on `:11434` answers `choice` / `noul` / `score` and writes no transcript: `POST /v1/chat/completions` → 501 `[MEASURED: research/d1-omni-capabilities.md]`. It cannot be this brain. The intended model is **LFM3-Omni** (generative text, images, audio) `[CITED: https://huggingface.co/LiquidAI/LFM3-Omni-2B]`. Today's d1-Omni process is the wrong shape; swapping it in is a brain prerequisite, not a game-install problem.

**5. Honest termination — designed, not yet wired.** Adapter outcomes `done / saturated / timeout / no_frame / pending` are the *contract* the next turn reads `[MEASURED: targeting-adapter.md §3]`, and the *machinery* that produces them exists. But a code audit of the current tree found that it does not reach a writer: `FLAG_SATURATED`, `residual_*_m`, `invalid_count` and `seq_ack` are computed inside the MuJoCo process and written to `<session>/body/body_state.json`, and `pose_relay.buttons_from_state` reads only `closure`/`trigger` while `wire.body_state_to_xr` reads only poses. `/api/state` returns the manager snapshot plus preview status, never `BodyState` `[MEASURED: audit of superbot/, 2026-10-31; see §11 and P2b].`

So the brain does not invent a second success oracle — but it also cannot currently read the first one. **Closing that path is a dependency of this spec, in the same class as freeze-hold (§6.1), not a proven basis.** Until it is closed, one-skill-per-turn still works; retry and VERIFY do not.

## 4. Proven basis

- Intent schema rejects unknown skills/sources, missing or spurious sides, pixels outside `[0, 1]`. Skills today: `hold | look | reach | grab | release | fire | strike | dodge | twitch`; sides required on `reach grab release fire strike dodge`; sources `human | vlm | planner | script`; default TTL 2000 ms; `yaw_rad` is head yaw for `look` without a pixel `[MEASURED: superbot/intent.py]`.
- Adapter: a writer names `skill + side + optional pixel`; glow is reported and is not an auto-grab; 2D→3D is out of the writer `[MEASURED: targeting-adapter.md, superbot/intent.py]`.
- Parent §8: `hold` means last achieved poses, not empty-mask return to clip. The executor today returns clip VR points when no head/hand bit is set `[MEASURED: spike/wbc/sonic_executor.py]`. Freeze-hold as specified here is the parent meaning. The clip return is a separate `rest`.
- Grip latches across empty-mask commands `[MEASURED: spike/wbc/sonic_executor.py]`. Freeze-hold must not reopen a hand.
- d1-Omni-2B-Q8_0 on `:11434` (llama-server `8ca4060`): no generated tokens; GPU digest 1q 62 ms, 3q 176 ms; image+1 `noul` 662 ms `[OPERATOR 2026-10-30; no method file in-tree]`. Useful later as an optional grounder. Not the planner.
- LFM3-Omni-2B: vendor generative omni (text/image/audio in, text or speech out), ~2.2B, ASR and audio understanding documented on the model card `[CITED: https://huggingface.co/LiquidAI/LFM3-Omni-2B]`. Latency and VRAM on this box for this job are **unmeasured**.
- `superbot/` stays stdlib-only. Image decode, HTTP, and any numpy grid live in `spike/`.

## 5. Goals and non-goals

### Goals

1. **Minimal seed.** A short constitution (body + output schema) plus one injected instruction. No walkthrough, no room map, no colour table, no Store Clerk FAQ.
2. **One skill per turn.** Planner emits one JSON action. The adapter runs it. The next turn sees the outcome and a new still.
3. **Speech is the task source.** JobBot (and any later voice) appends to a transcript. The model re-reads it. There is no parallel task list in code.
4. **Grounding is a second call.** Planner names a noun. Grounder returns a pixel or `not_visible`. The generator's JSON has no `pixel` field.
5. **Freeze-hold is the safe state.** Latch last-achieved head and wrist. Model, HTTP, and invalid-intent failures all go there.
6. **Operator click stays a writer** on the same socket. Omni down → freeze-hold, not a scripted Store Clerk.

### Non-goals (this spec)

- Launching or installing Job Simulator, OpenXR binding, Proton, audio-device plumbing as a product path. Those are other documents.
- Superhot paint, combat arbiter, incoming-fire reflex, hub FSM.
- A `HubFSM`, `insert`, `pull`, or `take_ticket` skill. Those are sequences of existing skills, discovered across turns.
- d1 as the v1 planner. A VLA at 50 Hz. Fine-tune. METATRON/UnifoLM/GR00T as this brain.
- Emitting a pixel, a 3D point, joints, or OpenXR poses from the generator.
- Walking. `fire` / `strike` / `dodge` in the constitution (they stay on the schema so the adapter does not fork).
- Changing `superbot/` away from stdlib-only.
- Rewriting the targeting adapter in this document. Freeze-hold (parent §8) is a **dependency** this spec assumes; it is specified there / in a hold rewrite, not here.

## 6. Architecture

```text
speech ends, or last skill terminates
        │
        v
SENSE      code        clip since last turn + still + BodyState + adapter outcome
MEMORY     code        seed + last K transcript lines + self + last action
PLAN       LFM3-Omni   → {skill, side, target?}          only in freeze-hold
GROUND     LFM3-Omni   if target set and skill needs where
           (grid)      → pixel | not_visible
ASSEMBLE   code        Intent; validate_intent; pixel only from GROUND
ACT        adapter     10–30 Hz   existing; one skill
BODY       SONIC       50 Hz      unchanged
VERIFY     code+Omni   outcome; optional "did that work?" on the new still
```

| Layer | Owns | Must not own |
| --- | --- | --- |
| SENSE | clip bounds, still, `BodyState`, adapter outcome | meaning |
| MEMORY | append-only transcript, last-K cap, self fields | a Store Clerk checklist |
| PLAN | which skill, which side, which noun | pixels, motion, timing inside a skill |
| GROUND | noun → pixel or `not_visible` | skill choice |
| ASSEMBLE | schema, rejection → freeze-hold | guessing a pixel when ground says no |
| ACT / BODY | servo, balance, packets | Job Simulator, speech, nouns |

Rules that hold across layers:

- **One skill per turn.** No 2–3 step plans in v1. Discovery of sequences is the point.
- **PLAN and GROUND run only in freeze-hold**, or after a skill has terminated. Never during motion. Never in the 50 Hz loop `[CITED: research/system1-game-agents.md; research/g1-language-to-action.md §5]`.
- **Deletion test.** Unplug Omni → freeze-hold; operator click still works. There is **no** arbiter that plays Job Simulator. That is accepted: the claim *is* the language brain.
- **Grab is never automatic on glow.** Glow, if present, is a live-context field. Closing the hand is its own intent `[MEASURED: superbot/intent.py]`.

### 6.1 Hold semantics

Same split as parent §8. This spec does not re-litigate the executor bug; it depends on the fix.

| Name | Authority | Targets | Who emits it |
| --- | --- | --- | --- |
| **freeze-hold** (`hold` in this spec) | head + both hands | last achieved poses | PLAN `hold`; any reject/timeout/stale/fall |
| **`rest`** | empty mask | clip VR points | not in the constitution; not a v1 planner output |

Grip already latches `[MEASURED: sonic_executor.py]`. Freeze-hold must not reopen a hand.

## 7. Prompt

Three layers. Only the first two are ours. The constitution is body knowledge. The seed is one instruction. Live is assembled every turn in code.

### 7.1 Constitution (stable)

Draft. Keep it this short. If a sentence is not body or schema, it does not belong here.

```text
You are a robot with two hands. You see one image from your eyes and
the speech since your last action.

You may do exactly one action:
- hold    keep still
- look    turn to look; name a target to look toward it, or omit to
          look a step left or right
- reach   move one hand toward a named thing
- grab    close one hand
- release open one hand

While holding something, reach moves it with that hand.

After each action you are told done, saturated, or timeout, and you
see a new image.

Reply with one JSON object only:
{"skill":"hold"|"look"|"reach"|"grab"|"release",
 "side":"none"|"left"|"right",
 "target": <noun string or null>}

side is none for hold and look, and left or right for reach, grab,
and release.

Do what the voice asked. Do not invent extra chores. If you cannot
see the thing, look. If you are unsure, hold.
```

`fire`, `strike`, `dodge`, `twitch`, `rest` are **absent** from this text on purpose.

### 7.2 Seed (injected once)

The only game hint. Example:

```text
use the store clerk cartridge
```

Not: how to insert a cartridge, where the tray is, that JobBot exists, Store Clerk's ticket / cans / camera, or any colour.

### 7.3 Live (every turn)

Assembled, not authored:

```text
heard: <verbatim new speech, or "(none)">
self:  left=<empty|holding> right=<empty|holding> yaw=<rad> glow=<yes|no|unknown>
last:  <skill> <side> target=<noun|null> → <done|saturated|timeout|no_frame|pending>
<image>
```

No task list. No "current goal:" line. The model re-derives intent from seed + transcript + this block.

## 8. Memory

Code, append-only.

```text
{
  "seed": "use the store clerk cartridge",
  "transcript": [
    {"t_mono_ns": ..., "text": "Hello human, why don't you take my business card"}
  ],
  "self": {"left": "empty"|"holding", "right": "empty"|"holding",
           "yaw_rad": float, "glow": "yes"|"no"|"unknown"},
  "last": {"skill": ..., "side": ..., "target": ..., "outcome": ...}
}
```

- **Transcript cap:** last **K = 10** lines plus seed. Older lines drop. If the model forgets an early instruction, that is a measured failure, not a reason to extract a checklist.
- **No structured todo list.** A todo list is how a walkthrough re-enters (`take_ticket`, `clear_cans`, `camera`).
- **`holding` is occupancy, not kind.** We do not ask the model "what am I holding" to fill `self`. Kind, if needed, is a GROUND/VERIFY question over the still.
- **Transcript text** is whatever Omni (or a dedicated ASR) wrote for the clip, stored as UTF-8. The log is how we debug "it did not hear him."

## 9. Planner output

One object. No other keys.

| Field | Allowed | Notes |
| --- | --- | --- |
| `skill` | `hold` `look` `reach` `grab` `release` | anything else → reject |
| `side` | `none` for `hold`/`look`; `left`/`right` for the rest | same rule as `validate_intent` |
| `target` | string noun or `null` | not a pixel, not an id we minted |

Then ASSEMBLE:

1. Parse JSON. Failure → freeze-hold, count `parse_fail`.
2. Map to `Intent` (`source="vlm"`). `target` is **not** an Intent field.
3. If skill is `look` and `target` is `null`: set `yaw_rad` to one step, alternating sign, magnitude `LOOK_ARC_RAD` already in `intent.py` `[MEASURED: superbot/intent.py]`. That is scan.
4. If skill is `look`/`reach`/`grab` and `target` is set: GROUND. Pixel in → Intent. `not_visible` → do **not** reach or grab; emit `look` with `target=null` (scan) or freeze-hold if we just scanned. Never invent a pixel.
5. `validate_intent`. Non-empty reason → freeze-hold, count the reason.
6. Post on the existing intent socket. Latest-wins, only in hold / after a ballistic, as the adapter already requires.

`grab` and `release` may carry a `target` for VERIFY's benefit; they do not need a new pixel if the hand is already there. If GROUND was `not_visible`, `grab` is illegal this turn.

TTL stays `DEFAULT_TTL_MS` unless a later measurement says otherwise.

## 10. Grounding

Hearing "take a ticket" is cheap. The salt-shaker `find()` row is this layer `[CITED: research/g1-language-to-action.md §4]`.

**v1 method:** a 3×3 grid over the still, cells `A B C / D E F / G H I` row-major, top-left origin to match Intent pixels. Second Omni call (or, later, optional d1 `choice` over the nine keys):

```text
Which cell contains: <noun>
Reply with one of A..I or none.
```

Pixel = cell centre in `[0, 1]`. `none` → `not_visible`.

Forbidden:

- Planner JSON containing `u`, `v`, `pixel`, or a bbox.
- `box` on the current llama.cpp d1 server (rejected on that build) `[MEASURED: research/d1-omni-capabilities.md]`.
- Superhot colour gates as the Job Simulator world.
- Treating glow as the location of `<noun>`.

If Omni is bad at the grid, that is an eval failure (§15), not a reason to put a walkthrough in the seed. A later optional d1 crop-choice head is allowed. It is not v1-required, and this spec must not assume both models fit in VRAM at once `[ASSUMPTION: d1-Omni already ~5.5 GiB model on this box, OPERATOR]`.

## 11. Verify and retry

| Signal | Who | What |
| --- | --- | --- |
| Adapter outcome | code | `done / saturated / timeout / no_frame / pending` |
| Occupancy | code | grip latched vs open → `self.left/right` |
| Optional look | Omni `noul` | "is `<noun>` in the `<side>` hand?" on the **new** still |

JobBot saying the next sentence is implicit success. Do not block on it. If the order is repeated, the new transcript line is the signal.

**Retry.** Same `(skill, side, target)` at most **twice** on a confirmed miss (`saturated` or `timeout` or VERIFY false). Then freeze-hold, and the next PLAN must change at least one of skill, side, or target (including a `look` with `target=null`). No grab-loop.

**`pending`.** Do not retry the same action until the adapter leaves `pending`.

**HTTP / parse / deadline.** Freeze-hold. Body ticks never block on the model. Deadline is a constant in the brain process; expiry is an allowed fail.

## 12. Reflexes

Tiny. No incoming-fire layer.

| Trigger | Response |
| --- | --- |
| Fall / tilt flag on `BodyState` | freeze-hold, `preempt=True` |
| Frame stale > 0.3 s | freeze-hold |
| Invalid intent, parse fail, model timeout | freeze-hold |

L2 never chooses the next chore and never resumes the aborted skill. After freeze-hold settles, PLAN sees a fresh still and the same transcript.

Until abort-during-ballistic is measured, only abort **non-ballistics** (`look`, `reach`). `grab`/`release` are button-like; treat them as abortable. Do not abort a `strike` this spec does not offer.

## 13. Models

**LFM3-Omni is the brain.** It hears, it sees, it chooses. d1 is not in the v1 loop.

| Job | Model | When |
| --- | --- | --- |
| Transcript line from the clip | LFM3-Omni ASR / audio understand | speech segment end |
| PLAN | LFM3-Omni, image + live text | freeze-hold |
| GROUND | LFM3-Omni grid, same still | after PLAN, same freeze |
| VERIFY noul (optional) | LFM3-Omni | after skill terminates |

Audio is **clip-level**, on speech end or a short window. Not a 50 Hz mic loop. LFM3-Audio `transcribe_live()` is a later swap if clip ASR lags; it is not required to accept this spec `[CITED: https://huggingface.co/LiquidAI/LFM3-Audio-2B]`.

**Three things this spec does not yet define, and they are not optional.** An audit of the tree found no audio input of any kind: `README.md` documents only an *output* mute (`POST /api/audio/mute`), and there is no microphone, no capture device, and no ASR model anywhere in `research/` `[MEASURED: audit 2026-10-31]`. Speech is currently **unmeasured on this machine — not weakly supported, unsupported.**

1. **Capture path.** Not chosen. The game runs in a hidden session, so the honest candidates are a PipeWire monitor of the game's sink (the dashboard already finds those nodes by `pw-dump` and acts with `wpctl`) or a loopback device. Whatever is chosen must land a 16 kHz mono WAV, because that is the only rate LFM3-Omni and d1-Omni accept. `audioop` was **removed in 3.13** (PEP 594) and this repo's devshell is 3.14 — do not plan on it.
2. **Segment boundary.** Not chosen. "Speech since last action" needs a definition: energy or zero-crossing gate, minimum and maximum clip length, silence hangover. JobBot's lines are discrete and widely spaced, so a simple hangover detector is *probably* sufficient `[ASSUMPTION]`. The functions must be pure over PCM, in the shape `framediff`/`glow` already use, so they are unit-testable without a sound card.
3. **Overlap.** Undefined. If JobBot speaks while a skill is running, the clip is kept and the transcript is appended at the next turn — do not interrupt a skill for speech. A repeated order is the retry signal (§11), not a preemption.

This is work order step **P0b**. It is a prerequisite in the same class as P0a, and it is the half of this design with *zero* local evidence behind it.

d1 may return as a fast "which cell is `<noun>`?" head if GROUND eval fails or Omni is too slow. Plug it in behind the same GROUND interface. Do not promote it to PLAN.

**Prerequisite:** a generative LFM3-Omni endpoint that actually emits tokens. The current `:11434` d1-Omni server cannot `[MEASURED: research/d1-omni-capabilities.md]`.

Latency on this box for LFM3-Omni PLAN+GROUND is `[UNKNOWN]`. The architecture assumes seconds are legal because the hands are frozen, not because a game clock is. If a call exceeds the deadline, freeze-hold and skip the turn.

## 15. Eval (replaces Superhot E5)

Frozen stills. No live game required to accept or reject this spec's brain. Labels from a human who can see the image and the transcript line, not from a script that already knows Store Clerk.

Frames: ~100 stills spanning museum hub and Store Clerk opening (card, tray, cartridges, slot, lever, ticket, cans, camera board/button), plus negatives (empty view, hands full, already holding the named thing). Label histogram is part of the report. A split with < 20% non-`hold` labels is invalid.

| Arm | Input | Bar | Gates play? |
| --- | --- | --- | --- |
| **Legal** | constitution + fixtures, no image needed | 100% parseable JSON; skill ∈ five; side rule holds | **yes** |
| **Seed** | hub still, seed only, `(none)` heard | first actions are look/reach toward tray/cartridges, not a clerk script and not `grab` at image centre as a habit | **yes** |
| **Speech-bind** | same still, heard = take my card | `target` is the card (or look toward it), not the cartridge | **yes** |
| **GROUND** | labelled cell for card/cartridge/slot/lever/ticket/can/button | hit-rate beats chance (1/9) with a named margin; report per class | **yes** for pixel skills |
| **Outcome-use** | still + `last: grab right card → saturated` | next action ≠ identical grab | **yes** |
| baseline | majority class | sanity floor | |

Pass Legal + Speech-bind + Outcome-use to put PLAN on the socket. Fail GROUND → PLAN may still emit `look`/`hold`; pixel skills stay off until GROUND passes. All fails are allowed fails: freeze-hold and log. Do not "fix" a fail by adding Store Clerk steps to the seed.

This is not "beat the arbiter." There is no arbiter.

## 16. Example (illustration, not a script)

Museum. Seed is `use the store clerk cartridge`. Constitution as in §7.1. **No Python branch on these nouns.**

1. Heard: "Hello human… take my card." PLAN: `look` / `reach` with `target="card"` (or "business card"). GROUND: cell of the card. Adapter reaches. `grab right`. Outcome `done`. Occupancy right=`holding`.
2. Heard: "grab a cartridge from the tray." Right is holding. PLAN may `release` onto a surface, or `look` at the tray first. Illegal: a coded `insert`.
3. `reach` + `grab` on the store clerk cartridge because the **seed** named it, not because a table maps "Store Clerk" → pixel.
4. Slot: `reach` the slot, `release`. Lever: `reach` the lever, `grab`, `reach` down (held object moves with the hand), `release`. If GROUND cannot see the lever, `look`, not a `pull` skill.

Store Clerk opening (ticket, cans, camera) is the same loop with new speech. If the seed is the only game text and JobBot has not spoken yet, the model is allowed to look around and hold. It is not allowed a hidden checklist.

## 17. Open risks

1. **LFM3-Omni is not on the box yet, or does not fit with the game.** Then this spec has no planner. d1 cannot substitute.
2. **GROUND at chance.** Then pixel skills are off and the demo is look-and-hold. Do not replace GROUND with a scripted pixel.
3. **The model writes a walkthrough anyway.** Constitution leak, or the still is so iconic it memorised the game. Eval Seed is the check. If it fails, shorten the constitution further; do **not** lengthen the seed.
4. **ASR garbage.** Transcript is wrong, PLAN follows it. Keep the clip; log both. A VERIFY miss should look, not insist.
5. **Freeze-hold still snaps to clip.** Thinking then drops the cartridge. Adapter hold rewrite is a hard dependency `[MEASURED: sonic_executor.py vs parent §8]`.
6. **One skill per turn is too slow for a human spectator, not for the claim.** Do not collapse into a 3-step compiler to make the video snappier. That is the hub FSM coming back.
7. **Occupancy ≠ identity.** Holding the wrong object looks like success to `self`. Optional VERIFY noul is the check; it can also be wrong. Log both.

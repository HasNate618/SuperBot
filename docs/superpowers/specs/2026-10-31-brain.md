## 1. Problem

The join works and the intent socket exists: a writer names `skill + side + optional pixel`, the adapter compiles that into `BodyCommand`s, the body never hears about a game `[MEASURED: clank/intent.py, docs/superpowers/specs/2026-10-30-targeting-adapter.md]`.

Parent §9 asked a **classifier** over a still and a short digest: skill + side, no 3D point, only in hold. The Superhot brain (2026-10-30) then specialised that into paint gates, a threat digest, and a code arbiter. That is the wrong specialisation for the claim we are making now.

The claim is **instruction following**. A voice in the world tells the robot what to do. The brain has almost no prior on the game. It hears, looks, emits one legal skill, sees the outcome, and tries again.

Job Simulator is the first writer because it *is* that loop: JobBot speaks, objects sit in reach, success is the next sentence or a visible change `[CITED: https://jobsimulator.fandom.com/wiki/JobBot]`. Superhot remains a possible later adapter on the same socket. It is not this spec.

## 2. Claim

A G1 that, given a **minimal seed** and live speech plus one image, emits a valid `clank.intent/1` and eventually completes spoken chores it was not scripted for.

Sequences are not compiled in Python. The model authors them across turns from `done / saturated / timeout`. If card → cartridge → slot → lever is a `HubFSM` in code, the brain is fake.

## 3. What makes this possible

In order. The model is last.

**1. A closed motor vocabulary.** Skills are `clank.intent/1` (rejected if unknown) `[MEASURED: clank/intent.py]`. Language is open. Motors are not. That is SayCan, not RT-2 `[CITED: research/system1-game-agents.md]`. The planner names a skill and a noun. It never names joints, an OpenXR pose, or a 3D point.

**2. Intent ≠ execution.** "Take a ticket" is two problems: grounding a noun in the image, and moving a hand. The adapter already owns the second. This spec owns the first, plus the choice of skill `[CITED: research/g1-language-to-action.md §1]`.

**3. The world waits.** Job Simulator does not shoot while we think `[ASSUMPTION: genre; not measured here]`. Thinking still happens only in freeze-hold so the wrists do not drift during a slow call. Freeze-hold is a body fact (last achieved poses), not a Superhot clock claim. Superhot G0 is not a gate for this spec.

**This is the weakest joint in the document, and it is stated as such on purpose.** The Superhot design was licensed by a *measured* clock (`minTimescale = 0.005 [MEASURED: research/wbc-game-proposal.md]`); this one is licensed by genre intuition. It is cheap to convert into a measurement and it should be, before B1: hold freeze for 20 s in a live Job Simulator scene and diff the stills. If nothing changes state — no objective timer, no JobBot re-prompt, no despawn — the assumption becomes a measurement. If something does change, the one-skill-per-turn cadence needs a shorter deadline. Do not leave this as an assumption once a session exists to test it in.

**4. A generative omni, not a decision head.** d1 answers `choice` / `noul` / `score` and writes no transcript: `POST /v1/chat/completions` → 501 `[MEASURED: research/d1-omni-capabilities.md]`. It cannot be this brain. **LFM3-Omni** is the brain (generative text, images, audio) `[CITED: https://huggingface.co/LiquidAI/LFM3-Omni-2B]`. As of 2026-11-01 it is the process on `:11434` and P0a is met. Do not put d1 back on that port.

**5. Honest termination — designed, not yet wired.** Adapter outcomes `done / saturated / timeout / no_frame / pending` are the *contract* the next turn reads `[MEASURED: targeting-adapter.md §3]`, and the *machinery* that produces them exists. But a code audit of the current tree found that it does not reach a writer: `FLAG_SATURATED`, `residual_*_m`, `invalid_count` and `seq_ack` are computed inside the MuJoCo process and written to `<session>/body/body_state.json`, and `pose_relay.buttons_from_state` reads only `closure`/`trigger` while `wire.body_state_to_xr` reads only poses. `/api/state` returns the manager snapshot plus preview status, never `BodyState` `[MEASURED: audit of clank/, 2026-10-31; see §11 and P2b].`

So the brain does not invent a second success oracle — but it also cannot currently read the first one. **Closing that path is a dependency of this spec, in the same class as freeze-hold (§6.1), not a proven basis.** Until it is closed, one-skill-per-turn still works; retry and VERIFY do not.

## 5. Goals and non-goals

### Goals

1. **Minimal seed.** A short constitution (body + output schema) plus a few injected facts the scene will not say clearly (§7.2). No walkthrough, no room map, no layout table, no Store Clerk FAQ. Identity is allowed ("the green STORE CLERK cartridge"). Positions are not.
2. **One skill per turn.** Planner emits one JSON action. The adapter runs it. The next turn sees the outcome and a new still.
3. **Speech is the task source.** JobBot (and any later voice) appends to a transcript. The model re-reads it. There is no parallel task list in code.
4. **Grounding is a second call.** Planner names a noun. Grounder returns a pixel or `not_visible`. The generator's JSON has no `pixel` field. Precision for close objects is a **wrist-crop verify after glow**, not a finer grid (§6.2, §10).
5. **Freeze-hold is the safe state.** Latch last-achieved head and wrist. Model, HTTP, and invalid-intent failures all go there.
6. **Operator click stays a writer** on the same socket. Omni down → freeze-hold, not a scripted Store Clerk.

### Non-goals (this spec)

- Launching or installing Job Simulator, OpenXR binding, Proton, audio-device plumbing as a product path. Those are other documents.
- Superhot paint, combat arbiter, incoming-fire reflex, hub FSM.
- A `HubFSM`, `insert`, `pull`, or `take_ticket` skill. Those are sequences of existing skills, discovered across turns.
- d1 as the v1 planner. A VLA at 50 Hz. Fine-tune. METATRON/UnifoLM/GR00T as this brain.
- Emitting a pixel, a 3D point, joints, or OpenXR poses from the generator.
- Walking. `fire` / `strike` / `dodge` in the constitution (they stay on the schema so the adapter does not fork).
- Changing `clank/` away from stdlib-only.
- Rewriting the targeting adapter in this document. Freeze-hold (parent §8) is a **dependency** this spec assumes; it is specified there / in a hold rewrite, not here.

## 6. Architecture

```text
speech ends, or last skill terminates
        │
        v
SENSE      code        clip since last turn + still + BodyState + adapter outcome
                       + glow (blue proximity) + ghost (yellow insert cue)
MEMORY     code        seed + last K transcript lines + self + last action
PLAN       LFM3-Omni   → {skill, side, target?}          only in freeze-hold
GROUND     LFM3-Omni   if target set and skill needs where
           (crop)      → pixel | not_visible
ASSEMBLE   code        Intent; validate_intent; pixel only from GROUND
                       occupancy; grab needs glow; insert-release needs ghost
ACT        adapter     10–30 Hz   reach servos until glow | ghost | saturated | timeout
BODY       SONIC       50 Hz      unchanged
VERIFY     Omni        after glow: wrist-crop "what is this?"; must match target
```

| Layer | Owns | Must not own |
| --- | --- | --- |
| SENSE | clip bounds, still, `BodyState`, adapter outcome, `glow`, `ghost` | meaning |
| MEMORY | append-only transcript, last-K cap, self fields | a Store Clerk checklist |
| PLAN | which skill, which side, which noun | pixels, motion, timing inside a skill |
| GROUND | noun → pixel or `not_visible` | skill choice; a layout table |
| ASSEMBLE | schema, occupancy, glow/ghost gates, rejection → freeze-hold | guessing a pixel when ground says no; auto-grab |
| ACT / BODY | servo, balance, packets, reach-until-cue | Job Simulator nouns, speech |

Rules that hold across layers:

- **One skill per turn.** No 2–3 step plans in v1. Discovery of sequences is the point.
- **PLAN and GROUND run only in freeze-hold**, or after a skill has terminated. Never during motion. Never in the 50 Hz loop `[CITED: research/system1-game-agents.md; research/g1-language-to-action.md §5]`.
- **Deletion test.** Unplug Omni → freeze-hold; operator click still works. There is **no** arbiter that plays Job Simulator. That is accepted: the claim *is* the language brain.
- **Grab is never automatic on glow. Release is never automatic on ghost.** Both cues are live-context fields. Closing or opening the hand is its own intent `[MEASURED: clank/intent.py]`.

### 6.2 First tasks (museum hub)

The system that does JobBot's opening is this loop with three code sensors (speech, occupancy, **Job Simulator cues**) and one extra model call (wrist-crop verify before grab). It is not a task planner, not a `HubFSM`, and not a fine-tune. Sequences are authored across turns from speech, occupancy, glow, ghost, and outcomes. The motors stay `hold | look | reach | grab | release`.

This section is the playbook for the first spoken chores. It does not add skills. Facts are `[OPERATOR 2026-11-01]` unless tagged otherwise.

#### Job Simulator in-range cues

Superhot's green slot and faint highlight (`clank/glow.py`, adapter §8) are the **wrong oracles** for this game. Job Simulator paints different colours:

| Cue | Looks like | Means | Who reads it | Legal next skill |
| --- | --- | --- | --- | --- |
| **Blue proximity** | a grabbable or interactable near the hand lights blue | in grab range now | adapter, patch around the projected wrist | `grab` (PLAN still emits it) |
| **Blue slot** | the cartridge slot itself is painted blue | where a held cartridge goes | GROUND (noun `"slot"`), or a hue-gate centroid as a 2D target | `reach` while holding |
| **Yellow ghost** | a yellow ghost of the cartridge appears at the slot | the game will accept a release | adapter, hue/appearance near the slot | `release` (insert) |

Conflating these produces a script that grabs at the slot from across the room (the slot is already blue) or that never releases (waiting for blue instead of yellow). The live block therefore carries **two** fields, not one:

- `glow` = blue proximity at the active wrist (`yes|no|unknown`)
- `ghost` = yellow ghost cartridge at the slot (`yes|no|unknown`)

Calibration is a pair of stills per cue (on/off), same rule as adapter S4. If the pair does not separate, the cue is abandoned and the operator calls range. Do not reuse Superhot's green constants.

#### Task by layer

| Beat | Who owns it | What happens |
| --- | --- | --- |
| Hear "here's my card" / "take my card" | SENSE | Clip → one transcript line. JobBot repeating the order is a second line, not a special retry. |
| Intend to take the card | PLAN | `{reach, right, "card"}`. Speech-bind measured on the recording `[MEASURED 2026-11-01]`. |
| Card out of view | GROUND + ASSEMBLE | `not_visible` → `look` scan (or `look` at "JobBot"). Next still has the card. No compiled "turn to JobBot" pose. |
| Reach until blue glow, then grab | Adapter, then PLAN | One `reach`. Adapter servos along the ray until `glow=yes` / `saturated` / `timeout`. Next turn sees `glow=yes` and may emit `grab`. |
| "Take a cartridge" while holding the card | Occupancy, not vision | `self: right=holding`. Either `release` then grab, or grab with the empty hand. ASSEMBLE already refuses `grab` on a full hand `[MEASURED: clank/brain.py assemble]`. Nothing in the seed about dropping; two hands are legal. |
| Pick STORE CLERK, not its neighbour | GROUND + VERIFY | Fill the frame with the tray, then name→quadrant `[MEASURED: 44/44 on one tray crop, /tmp/grounding-research.md]`. After `glow=yes`, crop around the wrist and ask "what is this?". Grab only if it matches. |
| Cartridges scatter on contact | The loop | New still, re-GROUND, new `reach`. A bump is `saturated` or a moved noun. Do not compile a trajectory. |
| Insert into the slot | Seed + same loop | Holding cartridge, `reach` slot (the slot is blue), wait until **`ghost=yes`**, `release`. The yellow ghost, not the slot's blue paint, is the insert oracle. |
| Pull the lever | Seed + constitution | `reach` lever, `grab`, then `reach` downward (held objects move with the hand). No `pull` skill. The lever reads "pull lever to job". |

#### Precision is a glow-gated verify, not a better pixel

Global image-space grids fail on this model: 3×3 thirds 3/12, 9-cell 0/12, 4×4 0/12 `[MEASURED 2026-11-01]`. Tray-crop name→position is 44/44 on one scene, and the identical prompt on the full frame is 9/12 (independent reproduction 2/4 vs 4/4). Accuracy tracks how much of the frame the container fills (63% fill → 4/4; 28% fill → 2/4).

The general primitive, pending a second-scene test:

1. Enumerate the scene on the full frame (measured 20/20 for this tray).
2. Crop so the named group's container fills the frame. **Automatic container detection is unbuilt**; the crop box in the measurement was hand-drawn.
3. Ask the single-target position question.
4. After `reach` stops on `glow=yes`, the container *is* whatever is in grab range — crop around the projected wrist and name it.

```text
glow=no                            → ASSEMBLE refuses grab
glow=yes + wrist-crop matches      → grab
glow=yes + wrist-crop mismatches   → do not grab; re-GROUND
ghost=no while inserting           → keep reaching
ghost=yes                          → release is legal this turn
```

That is how cartridges sitting ~7 cm apart (minimum label spacing 0.073 normalised `[MEASURED]`) are survived, and how a physics bump is recovered: the model is not tracking objects. It is re-asking on a new still.

A correct quadrant is not a precise pixel. Uncalibrated quadrant centres miss GOURMET CHEF by 0.097. Budget a per-quadrant offset or the wrist-crop verify; do not assume quadrant centre = cartridge.

#### Prompt rules measured 2026-11-01

**The prompt may never enumerate object positions.** A correct layout table scored 12/12; a deliberately false table scored 12/12 *following the lie* `[MEASURED: /tmp/grounding-research.md TABLE_wrong]`. Positions in the prompt make the model stop looking. Identity is allowed ("the green STORE CLERK cartridge"). Layout is not ("STORE CLERK is top-right").

At `temperature: 0` the model is byte-identical per (image, prompt). Majority vote and self-consistency are no-ops. Do not budget for them.

Colour is a weak general anchor: OFFICE WORKER's teal reads gray or red, and no colour maps to bottom-right. Attribute-anchoring worked for the green cartridge and is **not** the v1 grounder.

#### What has to exist, in order

The sequence cannot start without the body items. Replay (`spike/brainview`) stays the deterministic bed; the live game is only for envelope, glow colour, ghost, and physics.

**Body / adapter (no model)**

1. Freeze-hold = last achieved poses, not clip return. Thinking with a cartridge in hand otherwise drops it `[MEASURED: sonic_executor.py vs parent §8]`.
2. `reach` terminates on `glow` / `ghost` / `saturated` / `timeout`, and that outcome is visible to the next PLAN turn. `FLAG_SATURATED` is computed today and read by nobody `[MEASURED: audit 2026-10-31]`.
3. Job Simulator detectors: blue proximity at the wrist, yellow ghost at the slot. Calibrated on real on/off pairs. Superhot green is retired for this writer.
4. Envelope check on the live card: one operator click, one `reach`. If `SATURATED`, the milestone needs a lean/step and the brain cannot save it. **Unmeasured.** This is the cheapest thing that can still kill the milestone.

**Sense**

5. Live stills from the existing stdlib RFB client (`spike/vnc_grab.py` → `clank/frames.py::VncSource`).
6. Game audio via PipeWire (`pw-record` on the game sink) → 16 kHz mono WAV → one transcript line per speech segment. Replay already proved speech-bind with SRT slices `[MEASURED 2026-11-01]`; live capture is the unbuilt half.

**Brain (mostly written, wrong grounder)**

7. PLAN as specified (legal emit, occupancy, speech-bind).
8. GROUND swapped from global thirds to: enumerate or crop-container, then name→position; `not_visible` stays a look. No layout table in the prompt.
9. VERIFY as a grab gate: wrist-crop, "what is this?", must match `target`. Insert gate is `ghost=yes`, not a third model call.
10. Operator click stays a writer on the same socket, so a missed cartridge is a click, not a fine-tune.

#### What not to build

- No `insert` / `pull` / `take_cartridge` skill, and no Python `HubFSM`.
- No fine-tune on Job Simulator frames. Every failure this week was *how we asked*, not missing weights. A fine-tune would teach the tray layout — the memorised prior the permuted-collage control (16/16 on a new layout) proved we do not want — and would change the claim from "minimal seed, figures it out" to "trained on Job Simulator."
- No majority vote at `temperature: 0`.
- No walking.
- No d1 in the v1 loop.

#### Honest bounds

- Grounding 44/44 is one scene, one tray. Rule of three: 95% upper bound on per-query error ≈ 7%. A second container (register, tickets, camera button) is untested.
- Container crop is hand-supplied. Finding the container automatically is the remaining perception gap.
- Presence detection is unbuilt: the 2B model always answers; it claims a card in a frame with none.
- Reach to the live card is unmeasured.

## 7. Prompt

Three layers. Only the first two are ours. The constitution is body knowledge. The seed is one instruction. Live is assembled every turn in code.

### 7.1 Constitution (stable)

Draft. Keep it this short. If a sentence is not body or schema, it does not belong here.

```text
You are a robot with two hands. You see one image from your eyes and
the speech since your last action.

You may do exactly one action:
- hold    keep still
- look    turn to look; name a target to look toward it, or omit to
          look a step left or right
- reach   move one hand toward a named thing
- grab    close one hand
- release open one hand

While holding something, reach moves it with that hand.

After each action you are told done, saturated, or timeout, and you
see a new image.

Reply with one JSON object only:
{"skill":"hold"|"look"|"reach"|"grab"|"release",
 "side":"none"|"left"|"right",
 "target": <noun string or null>}

side is none for hold and look, and left or right for reach, grab,
and release.

Do what the voice asked. Do not invent extra chores. If you cannot
see the thing, look. If you are unsure, hold.

Grab only when glow is yes. A yellow ghost means the held thing will
go into the slot if you release. A full hand cannot grab; use the
other hand or release.
```

`fire`, `strike`, `dodge`, `twitch`, `rest` are **absent** from this text on purpose.

### 7.2 Seed (injected once)

Facts the scene will not say clearly. Still not a walkthrough. Amended 2026-11-01 because insert and the lever are not spoken as motor commands:

```text
use the store clerk cartridge (green label).
a cartridge goes in the glowing slot; a yellow ghost means you may release.
pull the lever down to start the job.
```

Identity is allowed (which cartridge, that a ghost means release). Layout is not. Not in the seed: JobBot exists, drop the card, wait for blue, the tray is a diamond, any pixel, any name→position table, any `reach`/`grab`/`release` sequence, Store Clerk's ticket / cans / camera.

### 7.3 Live (every turn)

Assembled, not authored:

```text
heard: <verbatim new speech, or "(none)">
self:  left=<empty|holding> right=<empty|holding> yaw=<rad>
       glow=<yes|no|unknown> ghost=<yes|no|unknown>
last:  <skill> <side> target=<noun|null> → <done|saturated|timeout|no_frame|pending>
<image>
```

`glow` is blue proximity at the active wrist. `ghost` is the yellow insert cue at the slot. They are independent: the slot can be blue from across the room while `glow=no` and `ghost=no`.

No task list. No "current goal:" line. The model re-derives intent from seed + transcript + this block.

## 8. Memory

Code, append-only.

```text
{
  "seed": "use the store clerk cartridge (green label). ...",
  "transcript": [
    {"t_mono_ns": ..., "text": "Hello human, why don't you take my business card"}
  ],
  "self": {"left": "empty"|"holding", "right": "empty"|"holding",
           "yaw_rad": float,
           "glow": "yes"|"no"|"unknown",
           "ghost": "yes"|"no"|"unknown"},
  "last": {"skill": ..., "side": ..., "target": ..., "outcome": ...}
}
```

- **Transcript cap:** last **K = 10** lines plus seed. Older lines drop. If the model forgets an early instruction, that is a measured failure, not a reason to extract a checklist.
- **No structured todo list.** A todo list is how a walkthrough re-enters (`take_ticket`, `clear_cans`, `camera`).
- **`holding` is occupancy, not kind.** We do not ask the model "what am I holding" to fill `self`. Kind, if needed, is a GROUND/VERIFY question over the still.
- **Transcript text** is whatever Omni (or a dedicated ASR) wrote for the clip, stored as UTF-8. The log is how we debug "it did not hear him."

## 9. Planner output

One object. No other keys.

| Field | Allowed | Notes |
| --- | --- | --- |
| `skill` | `hold` `look` `reach` `grab` `release` | anything else → reject |
| `side` | `none` for `hold`/`look`; `left`/`right` for the rest | same rule as `validate_intent` |
| `target` | string noun or `null` | not a pixel, not an id we minted |

Then ASSEMBLE:

1. Parse JSON. Failure → freeze-hold, count `parse_fail`.
2. Map to `Intent` (`source="vlm"`). `target` is **not** an Intent field.
3. If skill is `look` and `target` is `null`: set `yaw_rad` to one step, alternating sign, magnitude `LOOK_ARC_RAD` already in `intent.py` `[MEASURED: clank/intent.py]`. That is scan.
4. If skill is `look`/`reach`/`grab` and `target` is set: GROUND. Pixel in → Intent. `not_visible` → do **not** reach or grab; emit `look` with `target=null` (scan) or freeze-hold if we just scanned. Never invent a pixel.
5. Occupancy: `grab` on a holding hand, or `release` on an empty hand, → freeze-hold with the reason recorded. Two hands are legal; do not rewrite a full-hand `grab` into a `release`.
6. Cue gates: `grab` while `glow=no` → refuse (same class as occupancy). `release` of a held cartridge toward the slot while `ghost=no` → refuse; keep the last `reach`. Unknown cue (`unknown`) does not refuse — the adapter may still be calibrating; PLAN should prefer `hold` or continue `reach`.
7. `validate_intent`. Non-empty reason → freeze-hold, count the reason.
8. Post on the existing intent socket. Latest-wins, only in hold / after a ballistic, as the adapter already requires.

`grab` and `release` may carry a `target` for VERIFY's benefit; they do not need a new pixel if the hand is already there. If GROUND was `not_visible`, `grab` is illegal this turn. If `glow=no`, `grab` is illegal this turn. If inserting and `ghost=no`, `release` is illegal this turn.

TTL stays `DEFAULT_TTL_MS` unless a later measurement says otherwise.

## 10. Grounding

Hearing "take a ticket" is cheap. The salt-shaker `find()` row is this layer `[CITED: research/g1-language-to-action.md §4]`.

The 3×3 / 9-cell / 4×4 image-global pick is **retired** for this model. It collapses to the image centre: thirds 3/12, 9-cell 0/12, 4×4 0/12. OFFICE WORKER sits at (0.504, 0.495), six thousandths from the centre, which is why "always MIDDLE" looked like a prior `[MEASURED 2026-11-01]`.

**v1 method:** fill the frame with the noun's container, then ask a name→position question. Second Omni call, same still, freeze-hold:

```text
Which position in this tray does the {NAME} occupy?
Answer with one of: TOP-LEFT, TOP-RIGHT, BOTTOM-LEFT, BOTTOM-RIGHT.
```

Image: a crop of the container, resized to 1024 px wide, JPEG q95. Pixel = calibrated centre of the answered quadrant, composed back into full-frame `[0, 1]`. Uncalibrated quadrant centres are not accurate enough (GOURMET CHEF error 0.097). Prefer the wrist-crop VERIFY in §11 over a geometric centre.

When the container does not yet fill the frame:

1. Enumerate on the full frame (`List the named things and where each sits`). Measured 20/20 for the four cartridges.
2. Crop so that group fills most of the frame. Accuracy tracked fill fraction on one scene: 63% → 4/4, 28% (full frame) → 2/4.
3. Then the single-target question above. Measured 44/44 on one tray crop across 1024/1600/2048 px; the identical prompt on the full frame was 9/12.

`none` / unparseable / a name that is not in the image → `not_visible`. Presence detection is **unbuilt**: the model always answers something. A crop of an empty region is not a reliable negative.

**Automatic container detection is unbuilt.** The measured crop bbox was hand-drawn. Until a detector exists, the operator click is the fallback writer on the same socket, and a coarse reach plus glow-gated VERIFY is the live path.

Forbidden:

- Planner JSON containing `u`, `v`, `pixel`, or a bbox.
- A layout table in the prompt (name, colour, position). Measured 12/12 following a deliberately false table.
- `box` on the current llama.cpp d1 server (rejected on that build) `[MEASURED: research/d1-omni-capabilities.md]`.
- Superhot colour gates as the Job Simulator world.
- Treating glow as the location of `<noun>`. Glow is a range cue at the wrist, not a finder.
- Image-global 3×3 / 9-cell / 4×4 as the grounder.
- Colour-then-position as the general method (OFFICE WORKER unreachable by colour).
- Majority vote or self-consistency at `temperature: 0`.

A later optional d1 crop-choice head is allowed. It is not v1-required, and this spec must not assume both models fit in VRAM at once `[ASSUMPTION: d1-Omni already ~5.5 GiB model on this box, OPERATOR]`.

## 11. Verify and retry

| Signal | Who | What |
| --- | --- | --- |
| Adapter outcome | code | `done / saturated / timeout / no_frame / pending` |
| Occupancy | code | grip latched vs open → `self.left/right` |
| Blue proximity | adapter | `glow` at the projected wrist; grab gate |
| Yellow ghost | adapter | `ghost` at the slot; insert-release gate |
| Wrist-crop (grab) | Omni | after `glow=yes`, crop around the wrist, "what is this?". Grab only if it matches `target`. |
| Optional look | Omni | "is `<noun>` in the `<side>` hand?" on the **new** still |

JobBot saying the next sentence is implicit success. Do not block on it. If the order is repeated, the new transcript line is the signal.

Wrist-crop is the precision mechanism for the tray. Four cartridges sit closer together than a 3×3 cell. The model is not asked for a millimetre; it is asked, after the game has highlighted *one* object, to name that object. A mismatch is `VERIFY false`, not a grab.

**Retry.** Same `(skill, side, target)` at most **twice** on a confirmed miss (`saturated` or `timeout` or VERIFY false). Then freeze-hold, and the next PLAN must change at least one of skill, side, or target (including a `look` with `target=null`). No grab-loop.

**`pending`.** Do not retry the same action until the adapter leaves `pending`.

**HTTP / parse / deadline.** Freeze-hold. Body ticks never block on the model. Deadline is a constant in the brain process; expiry is an allowed fail.

## 12. Reflexes

Tiny. No incoming-fire layer.

| Trigger | Response |
| --- | --- |
| Fall / tilt flag on `BodyState` | freeze-hold, `preempt=True` |
| Frame stale > 0.3 s | freeze-hold |
| Invalid intent, parse fail, model timeout | freeze-hold |

L2 never chooses the next chore and never resumes the aborted skill. After freeze-hold settles, PLAN sees a fresh still and the same transcript.

Until abort-during-ballistic is measured, only abort **non-ballistics** (`look`, `reach`). `grab`/`release` are button-like; treat them as abortable. Do not abort a `strike` this spec does not offer.

## 13. Models

**LFM3-Omni is the brain.** It hears, it sees, it chooses. d1 is not in the v1 loop.

| Job | Model | When |
| --- | --- | --- |
| Transcript line from the clip | LFM3-Omni ASR / audio understand | speech segment end |
| PLAN | LFM3-Omni, image + live text | freeze-hold |
| GROUND | LFM3-Omni, container crop then name→position, same still | after PLAN, same freeze |
| VERIFY wrist-crop (grab gate) | LFM3-Omni | after `glow=yes`, before `grab` |

Audio is **clip-level**, on speech end or a short window. Not a 50 Hz mic loop. LFM3-Audio `transcribe_live()` is a later swap if clip ASR lags; it is not required to accept this spec `[CITED: https://huggingface.co/LiquidAI/LFM3-Audio-2B]`.

**Replay speech is measured; live capture is not.** SRT-sliced clips of the walkthrough bind "take my card" to `target="card"` `[MEASURED 2026-11-01]`. An audit of the tree still found no *live* audio input: `README.md` documents only an *output* mute (`POST /api/audio/mute`). P0b-replay is pass; P0b-live is unbuilt.

1. **Capture path.** Not chosen. The game runs in a hidden session, so the honest candidates are a PipeWire monitor of the game's sink (the dashboard already finds those nodes by `pw-dump` and acts with `wpctl`) or a loopback device. `pw-record` is present; `parec`/`pactl` are not. Whatever is chosen must land a 16 kHz mono WAV. `audioop` was **removed in 3.13** (PEP 594) and this repo's devshell is 3.14 — do not plan on it.
2. **Segment boundary.** Replay used the SRT as ground truth (`ffmpeg silencedetect` produced 21 fragments for 4 subtitle blocks). Live still needs a definition: energy gate, minimum and maximum clip length, silence hangover. JobBot's lines are discrete and widely spaced, so a simple hangover detector is *probably* sufficient `[ASSUMPTION]`. The functions must be pure over PCM, in the shape `framediff`/`glow` already use, so they are unit-testable without a sound card.
3. **Overlap.** If JobBot speaks while a skill is running, the clip is kept and the transcript is appended at the next turn — do not interrupt a skill for speech. A repeated order is the retry signal (§11), not a preemption.

d1 may return as a fast crop-choice head if GROUND eval fails or Omni is too slow. Plug it in behind the same GROUND interface. Do not promote it to PLAN.

Latency on this box for LFM3-Omni PLAN+GROUND is ~0.6 s per replay turn, audio-only prefill 197 ms `[MEASURED 2026-11-01]`. The architecture assumes seconds are legal because the hands are frozen, not because a game clock is. If a call exceeds the deadline, freeze-hold and skip the turn.

**Prerequisite P0a is met** on the current `:11434` LFM3-Omni process. The old d1-Omni 501 finding remains true of *that* binary; do not put d1 back on this port.

## 16. Example (illustration, not a script)

Museum. Seed as in §7.2. Constitution as in §7.1. **No Python branch on these nouns.** This is §6.2 in sequence form.

1. Heard: "Here's my card. Hey human, take my card." PLAN: `look` / `reach` with `target="card"`. Card out of view → GROUND `not_visible` → ASSEMBLE downgrades to `look` (scan, or toward "JobBot"). Next still has the card.
2. GROUND returns a pixel. Adapter `reach` until `glow=yes` (blue on the card) or `saturated`/`timeout`. Next PLAN sees `glow=yes` and emits `grab`. Occupancy right=`holding`.
3. Heard: "grab one of the job cartridges." Right is holding. PLAN uses the empty hand, or `release` then grab. ASSEMBLE refuses `grab` on the full hand. Seed named STORE CLERK (green); no layout table.
4. GROUND crops the tray, asks name→position, reaches that quadrant. Cartridges are close and have physics: if the hand bumps them, the next still is the world, and GROUND runs again. `glow=yes` on a neighbour + wrist-crop saying GOURMET CHEF → do not grab.
5. Holding the green cartridge: `reach` the slot (painted blue). Keep reaching until **`ghost=yes`** (yellow ghost cartridge). Then `release`. The slot being blue from afar is not a release cue.
6. Lever: `reach` the lever, `grab`, `reach` down (held object moves with the hand), `release`. If GROUND cannot see the lever, `look`, not a `pull` skill.

Store Clerk opening (ticket, cans, camera) is the same loop with new speech. If the seed is the only game text and JobBot has not spoken yet, the model is allowed to look around and hold. It is not allowed a hidden checklist.

## 17. Open risks

1. **LFM3-Omni does not fit with the game.** P0a is met on `:11434` alone. Co-residency with Job Simulator + MuJoCo is unmeasured. d1 cannot substitute.
2. **GROUND at chance on a second scene.** 44/44 is one tray. Pixel skills stay off until E1 on a labelled set that is not that one image. Do not replace GROUND with a scripted pixel.
3. **The model writes a walkthrough anyway.** Constitution leak, or the still is so iconic it memorised the game. Eval Seed is the check. If it fails, shorten the constitution; do **not** lengthen the seed with a sequence.
4. **ASR garbage.** Transcript is wrong, PLAN follows it. Keep the clip; log both. A VERIFY miss should look, not insist. Live capture is unbuilt.
5. **Freeze-hold still snaps to clip.** Thinking then drops the cartridge. Adapter hold rewrite is a hard dependency `[MEASURED: sonic_executor.py vs parent §8]`.
6. **One skill per turn is too slow for a human spectator, not for the claim.** Do not collapse into a 3-step compiler to make the video snappier. That is the hub FSM coming back.
7. **Occupancy ≠ identity.** Holding the wrong cartridge looks like success to `self`. Wrist-crop VERIFY is the check; it can also be wrong. Log both.
8. **Live card is out of reach.** Envelope unmeasured. `SATURATED` on the operator-click reach means the milestone needs a lean/step; the brain cannot save it.
9. **Wrong glow oracle.** Superhot green, or treating the slot's persistent blue as `glow=yes`, makes grab/insert fire at the wrong time. Yellow ghost is the insert cue.
10. **Container box stays hand-drawn.** Then live GROUND is operator-assisted. Active perception (coarse reach + glow + wrist-crop) is the fallback, not a fine-tune.
